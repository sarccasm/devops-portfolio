# Лабораторна робота №3 — Власний DevOps-інструментарій

**Основні завдання: 8 балів. Бонусні завдання: до 6 балів.**

## Мета роботи

Розробити власні інструменти для автоматизації DevOps-процесів: резервного копіювання, моніторингу API та перевірки коду за допомогою Git-хуків.

**Технології:** Bash, Python 3.11+, Go 1.20+, Git, ShellCheck, Ruff.

Bash-скрипти запускаються в Linux, macOS або Git Bash. Системний монітор `monitor.sh` призначений лише для Linux.

## Структура проєкту

- `backup.sh` — резервне копіювання та ротація архівів.
- `api_monitor.py` — моніторинг доступності API.
- `config/` — конфігураційні файли.
- `hooks/` — Git-хуки `pre-commit` та `pre-push`.
- `install-hooks.sh` — встановлення Git-хуків.
- `monitor.sh` — моніторинг системи Linux (бонус).
- `log_analyzer.py` — аналіз журналів вебсервера (бонус).
- `file_sorter.go` — сортування файлів (бонус).
- `tests/` — автоматичні тести.
- `samples/` — приклади вхідних даних.

## 1. Резервне копіювання — backup.sh

Скрипт створює стиснені архіви `.tar.gz`, додає часову мітку до назви, зберігає задану кількість останніх копій та записує результати в журнал.

**Приклад запуску (Git Bash):**

```bash
./backup.sh --source "./samples" --dest "./backups" --keep 3
./backup.sh --source "./samples" --dest "./backups" --keep 3 --dry-run
```

**Параметри:**
- `--source` — папка для резервного копіювання.
- `--dest` — папка збереження архівів.
- `--keep` — кількість останніх копій.
- `--dry-run` — перегляд дій без зміни файлів.
- `--help` — довідка.

**Пояснення `set -euo pipefail`:**

- `-e` — завершує скрипт у разі необробленої помилки.
- `-u` — забороняє використання невизначених змінних.
- `pipefail` — виявляє помилки всередині конвеєрів команд.

Без цих параметрів скрипт може продовжити виконання після помилки, використати неправильні значення або приховати збій команди.

## 2. Моніторинг API — api_monitor.py

Інструмент перевіряє HTTP(S)-адреси, визначає несправності, виконує одну повторну спробу після мережевої помилки та зберігає JSON-звіт.

**Запуск:**

```bash
python api_monitor.py --config config/endpoints.json --output monitor-results.json
```

Конфігурація містить URL, очікуваний HTTP-код, тайм-аут і допустимий час відповіді.

**Типи збоїв:**

| Тип | Причина |
|---|---|
| DNS | Домен не знайдено |
| Connection refused | Сервер або порт відхиляє з'єднання |
| Timeout | Сервер не відповів вчасно |
| Certificate error | Помилка SSL/TLS-сертифіката |
| Unexpected status | Неочікуваний HTTP-код |
| Slow response | Перевищено допустимий час відповіді |

**Відмінність між connection refused і timeout:**

`Connection refused` означає, що TCP-з'єднання відхилено, наприклад, через непрацюючий сервіс або закритий порт. `Timeout` означає, що відповідь не отримана за встановлений час. Причиною може бути мережева проблема, перевантаження чи зависання застосунку.

Для сповіщень Discord використовується змінна середовища `MONITOR_WEBHOOK_URL`. Секретний токен не зберігається у вихідному коді.

**Коди завершення:** `0` — успіх, `1` — знайдено проблеми, `2` — помилка конфігурації, `3` — помилка запису звіту.

## 3. Інтеграція з Git

Реалізовано два Git-хуки:

**pre-commit:** перевіряє лише файли, додані до коміту. Для Bash використовується ShellCheck, для Python — Ruff та перевірка синтаксису.

**pre-push:** запускає автоматичні Python-тести перед відправленням змін на GitHub.

**Встановлення (Git Bash):**

```bash
bash lab-03/install-hooks.sh
```

Команду потрібно виконувати з кореня Git-репозиторію.

**Чому Git-хуки не є повноцінним захистом?**

Git-хуки працюють локально на комп'ютері розробника. Їх можна вимкнути або обійти через `--no-verify`. Тому обов'язкові перевірки потрібно виконувати також у CI, наприклад GitHub Actions, із відповідними правилами захисту гілок.

## 4. Бонус: моніторинг Linux

Скрипт `monitor.sh` перевіряє використання CPU, RAM, диска та стан системних сервісів.

Пороги налаштовуються у `config/system.env`.

```bash
./monitor.sh --config config/system.env
```

Якщо значення перевищує поріг, скрипт записує `ALERT` у журнал і повертає ненульовий код завершення.

Для автоматичного запуску можна використовувати `cron`.

## 5. Бонус: аналізатор логів

`log_analyzer.py` обробляє журнали Apache/Nginx у форматі Combined Log.

Він визначає найактивніші IP-адреси, статистику HTTP-кодів, години пікового навантаження та кількість некоректних записів.

```bash
python log_analyzer.py --input samples/access.log --output reports/report.txt --format text --top 5
```

Некоректні рядки підраховуються окремо та не зупиняють аналіз.

## 6. Бонус: утиліта на Go

`file_sorter.go` розподіляє файли за категоріями: документи, зображення, відео, архіви та інші.

```bash
go run file_sorter.go -dir ./samples -dry-run
go test ./...
```

Режим `-dry-run` показує майбутні дії без переміщення файлів.

**Порівняння Go та скриптів:**

Go-програма компілюється у виконуваний файл і може працювати без окремого інтерпретатора. Вона підходить для переносимих утиліт зі складнішою логікою. Bash і Python зручніші для швидкої автоматизації та простих завдань. Водночас скомпільований Go-файл зазвичай займає більше місця.

## 7. Тестування

Перевірка Python:

```bash
python -m unittest discover -s tests -v
python -m ruff check .
```

Перевірка Bash:

```bash
shellcheck backup.sh monitor.sh install-hooks.sh hooks/pre-commit hooks/pre-push tests/test_backup.sh
bash tests/test_backup.sh
```

Перевірка Go:

```bash
go test ./...
```

**Результати:** локальні Python- і Go-тести, Ruff, ShellCheck та Git-хуки пройшли перевірку. GitHub Actions також завершив CI-перевірку успішно.
